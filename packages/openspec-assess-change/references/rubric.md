# Rubric: профиль change (schemaVersion 1)

Профиль описывает **сам change**, а не модели. Его заполняет агент по якорям ниже; CLI проверяет структуру, ссылки и digest, но не объявляет суждение агента доказанным.

## Состояния и виды фактов

| Поле | Значения | Правило |
| --- | --- | --- |
| `state` | `known`, `unknown`, `not-applicable` | `unknown` никогда не равен 0: индексы получают границы 0–4, ранжирование — консервативный уровень `complexityRules.unknownRankingLevel` (по умолчанию 3). `not-applicable` требует `rationale` и исключается из сумм. |
| `kind` | `measured`, `declared`, `estimated` | `measured` — только с evidence измерения (`diff`, `check-result`) и точным значением (`min == max`). `declared` — суждение по артефактам. `estimated` — прогноз (диапазон). |
| `level` | 0–4 | 0 = минимальная трудность *применимого* фактора; отсутствие фактора — `not-applicable`. |

Каждое `known`-значение требует `level`/`min`+`max`, `kind`, `rationale` (назовите якорь) и `evidence` (ID из списка evidence).

## Evidence

| `kind` | Обязательные поля | База пути | Что проверяет CLI |
| --- | --- | --- | --- |
| `artifact` | `path` | `change` | существование, digest |
| `requirement` | `path`, `locator` = имя Requirement | `change` | строка `### Requirement: <locator>`, digest |
| `task` | `path`, `locator` = ID задачи | `change` | строка `- [ ] <id>`, digest |
| `file` | `path` | `repo` | существование, digest; `planned: true` — файла ещё нет, нужен `derivedFrom` на task/requirement/artifact, digest запрещён |
| `check-result` | `path` | `repo` | файл результата проверки (лог тестов и т.п.), digest |
| `diff` | `revision` | — | digest `git diff --binary <revision>` + неотслеживаемые файлы, без каталога `assessment/` этого change |

Digest не пишутся вручную: `pin-evidence` заполняет недостающие и отказывается перезаписать отличающийся (источник изменился — перечитайте его и удалите старый digest). Для `tasks.md` digest считается без учёта отметок `[x]`: прогресс apply не делает план устаревшим, изменение текста задачи — делает. Пути не могут выходить за корень (включая symlink).

## Количества

`quantities`: `tasks`, `files`, `diffLines`, `generatedFiles`. До реализации — `estimated` с диапазоном («5–8 файлов» → `min: 5, max: 8`), планируемые файлы — `planned`. Перед verify — `measured` по diff. `generatedFiles` отображается отдельно и не входит в объём.

Уровень `volume` выводится, а не задаётся: каждый количественный показатель переводится в уровень порогами `complexityRules.volumeThresholds` (`tasks: 1,4,10,25`, `files: 1,4,12,40`, `diffLines: 50,300,1200,5000`; значение выше i-го порога даёт уровень i+1), берётся максимум. Число файлов **не** влияет на остальные факторы.

## Факторы и якоря

Якоря — `RUBRIC` в `src/core/factors.mjs` (это источник истины; таблица ниже совпадает).

| Фактор | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| `domains` — домены и связи | один домен, связи не меняются | один домен, незначительная связь с соседним | два домена или существенная связь между ними | три+ домена или изменение границ ответственности | сквозное изменение многих доменов |
| `layers` — слои и пересечения | одна категория, без пересечений | одна категория + локальное касание соседней | две категории, одно пересечение границы | три+ категории или несколько пересечений | сквозь большинство слоёв с согласованием контрактов |
| `architecture` | нет новых компонентов/контрактов/зависимостей | локально внутри компонента | новый компонент или внутренний контракт | смена ответственности или внешних зависимостей | новая архитектура подсистемы |
| `logic` | механические правки | простое ветвление/преобразование | нетривиальный алгоритм, средняя state machine | сложные алгоритмы, конкурентность, многие инварианты | распределённое состояние, гонки |
| `compatibility` | без влияния на публичные контракты и данные | аддитивное изменение API/формата | совместимое изменение формата, простая миграция | ломающее изменение с миграцией данных | необратимая миграция, много потребителей |
| `testability` (сложность проверки) | точный oracle, локально и быстро | oracle + небольшие fixtures | integration или неполный oracle | runtime-зависимости, частично ручная проверка | нет надёжного oracle, внешние системы |
| `consequences` | ошибка безвредна и видна сразу | локальный дефект, лёгкий откат | затрагивает пользователей функции | безопасность, целостность данных, широкий blast radius | утечка/потеря данных, обход авторизации, необратимость |
| `uncertainty` | решения закрыты, acceptance criteria полные | мелкие открытые детали | открытые решения с ограниченным влиянием | существенные открытые решения | ключевые решения неизвестны |

Слои — категории (`ui`, `api`, `domain`, `data`, `infrastructure`, `build`, `config`, `docs`, `tests`, `security`, `tooling`) в `details.layerCategories`; универсального «frontend проще infrastructure» нет — оцениваются переходы и навыки. Для доменов можно указать `details.domainIds` и `details.links`.

## Свойства change

Из уровней CLI считает четыре **независимых** индекса 0–10000 bp (нижняя, ранжирующая и верхняя границы): `volume` (объём), `complexity` (domains 2, layers 1, architecture 3, logic 3, compatibility 1), `risk` (consequences 3, compatibility 2, testability 2), `uncertainty`. Веса — `complexityRules.groups`. Модели, цены и квоты эти индексы не меняют.

## Два контрольных примера

- **Большое механическое изменение** (переименование логгера в 60–80 файлах): `volume` 4, `architecture` 0, `logic` 0 → высокий индекс объёма при низкой сложности, показанные раздельно (`test/change.test.mjs`).
- **Малое критичное изменение** (одна проверка авторизации, 1–2 файла): `volume` ≤ 1, но `consequences` 4 → индекс риска ≥ 5000, для verify срабатывает критическое ограничение по `consequences`.

## Пример

`examples/demo-project/openspec/changes/add-shout-flag/assessment/profile.json` — заполненный профиль искусственного change с evidence на proposal, design, tasks, requirement, существующие файлы и планируемый `docs/usage.md`. `node examples/run-example.mjs` пинует и валидирует его во временной копии.
